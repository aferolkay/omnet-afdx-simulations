# afdxSimulations

Simulation scenarios for the AFDX network model, kept separate from the AFDX
library implementation itself.

## Dependencies

This project does not vendor the AFDX model code. It builds against two
sibling OMNeT++ projects that must be checked out next to this repo (as
referenced by `.project`):

- **afdx** — the AFDX end system / switch / cable NED and C++ model
- **queueinglib** — supporting queueing library used by the AFDX model

Expected layout:

```
<workspace>/
├── afdxSimulations/   (this repo)
├── afdx/
└── queueinglib/
```

`src/Makefile` (generated by `opp_makemake`) locates these via the
`AFDX_PROJ` and `QUEUEINGLIB_PROJ` variables. If your checkout paths differ
from the defaults, regenerate the makefile:

```
cd src
opp_makemake -f --deep -KAFDX_PROJ=<path-to-afdx> -KQUEUEINGLIB_PROJ=<path-to-queueinglib> \
  -DQUEUEING_IMPORT -I$(QUEUEINGLIB_PROJ) -L$(AFDX_PROJ)/src -L$(QUEUEINGLIB_PROJ) \
  -lafdx$(D) -lqueueinglib$(D)
```

## Building and running

```
make makefiles   # generate src/Makefile via opp_makemake, if not present
make              # builds the executable into src/
cd simulations
./run             # runs the built executable against simulations/omnetpp.ini
```

`src/` contains no simulation-specific C++ of its own — it exists only as
the OMNeT++ build root that links against `afdx` and `queueinglib` to
produce the executable used by `simulations/run`.

## Adding a new simulation

Each simulation lives in its own self-contained folder under
`simulations/networks/<name>/`, containing everything it needs:

```
simulations/networks/<name>/
├── <name>.ned
├── <name>.ini
├── switchRouteTable.txt   (or other per-simulation data files)
└── .qtenvrc
```

Register it by adding an `include` line to `simulations/omnetpp.ini`:

```
include networks/<name>/<name>.ini
```

File paths referenced from within a simulation's `.ini` (e.g.
`configTableName`) are resolved relative to `simulations/`, since that's
the directory simulations are run from — keep such paths as
`networks/<name>/<file>`, not `../`-relative paths that reach outside the
simulation's own folder.
